# Analysis Repository Design

The application owns the repository port and publication eligibility. The Neo4j adapter owns mapping, schema inspection, replacement, and database resources. The [analysis contract](../contracts/analysis.md#publication-eligibility) defines caller outcomes; the [schema](../repository/neo4j-schema.md) defines the stored surface.[1][2]

## Responsibilities and dependencies

| Owner | Responsibility |
| --- | --- |
| `AnalysisCapabilities` | Compose independent application inputs from their required collaborators, without acquiring storage. |
| `AnalysisExecutionCoordinator` / `StandaloneAstRetention` | Invoke the shared publication policy with a coordinated run or standalone AST subject, respectively. |
| `PublicationCoordinator` / `OwnedRepository` | Own eligibility, subject identity, outward failure classification, lazy acquisition, and closure before `SAVED`. Track only the replacement observations available at the application boundary. |
| `RetainedAstQuery` | Acquire one exact lookup, validate its returned identity, and close before returning any normal lookup status. |
| `application.port` | Own AST and completed-run repository/factory interfaces and the extensible failure contract independently of Neo4j. |
| Composition root | Supply the concrete adapter and connection settings. |
| `Neo4jRepositories` | Compose separate lazy factories through `astRetention`, `astQuery`, and `completedRuns`. Forward the deferred settings supplier. |
| `Neo4jAnalysisRunRepository` / `Neo4jAstResultRepository` | Own storage work through adapter-local operation scopes; preserve distinct run and AST replacement namespaces. |
| `Neo4jRepositoryAcquisition` | Resolve deferred settings through the acquisition operation, acquire the driver and session configuration, and arrange cleanup of accessible resources before a failed transfer. |
| `Neo4jRepositoryOperation` | Observe adapter phases and failure translation, manage session scopes and driver closure, and record conservative replacement knowledge. |
| `Neo4jIdentityConstraints` | Supply the required definitions for each namespace through one mechanism for constraint creation, metadata selection, and exact verification. |
| `Neo4jStoredAstAdmission` / `Neo4jAstResultCodec` | Interpret detached stored AST facts and compare the materialization with the intrinsically admitted source result. |
| `Neo4jAstReconciliation` / `Neo4jAstMaterialization` | Decide what to retain, change, or remove for one AST replacement attempt, and apply those decisions in the transaction. |
| `Neo4jAnalysisRunMapper` and focused mappers | Convert a completed run into a projection without accessing the driver. |
| `Neo4jProjectionBuilder` and projection values | Confine mutation to one mapping operation and validate identities, properties, ordering, and endpoints before publication. |
| Direct repository caller | Supply a truthful completed run and close the repository it opened. |

Application and CLI code depend on application-owned ports. The CLI composition root supplies the concrete adapter. Adapter dependencies and the remaining permitted package directions are enforced by the [build architecture policy](../build-quality.md#architecture-policy).[1][2][3][5][7][8]

## Publication phases and failures

`save` rejects a null run with `NullPointerException` before assigning a new operation context or opening a session. For a nonnull run it establishes the run's exact context before mapping outside database-exception translation. The mapper requires `isPublishable()` to hold. The adapter then prepares schema in one session, inspects both required named constraints, and closes that session before replacement. Definition inspection checks name, uniqueness type, node entity type, label, and ordered properties.[2][3]

Replacement opens a separate session and executes a managed write callback. Each attempt deletes existing `AnalysisEntity` nodes for the supplied `runId`, creates the replacement nodes, and creates their relationships. The immutable projection is created before the callback, so driver replay does not remap the input.[2]

| Phase | Failure or partial-effect boundary |
| --- | --- |
| Driver acquisition | If later setup fails after returning an accessible driver, attempt driver close and preserve the original failure with cleanup evidence. |
| Mapping and projection validation | No schema or replacement effect has started. Preserve the actual throwable family. |
| Schema creation and inspection | Constraint effects may remain after a later failure. Missing, incompatible, or unreadable required definitions prevent replacement. |
| Schema-session close | Close must finish normally before opening the replacement session. |
| Managed replacement | Delete and recreate belong to one transaction per attempt. An established noncommit preserves the old projection; missing commit acknowledgement leaves whole-run commit unknown. |
| Publication-session close | A failure after known commit does not undo the committed projection. |
| Repository close | The application attempts close before returning `SAVED`; close failure does not prove rollback or resource release. |

Both repository families use the same operation observer. Acquisition translates configuration `IllegalArgumentException` and driver `Neo4jException` into `RepositoryException` in its declared acquisition regions. Schema/replacement/read/session-close/driver-close regions translate effective `Neo4jException`; mapping/admission failures retain their actual family. The adapter wraps runtime failures in `Neo4jRepositoryOperationException` after translation. The application's [shared crossing](../contracts/analysis.md#target-repository-failure-crossing) decides returned `FAILED` versus abrupt publication and retains the computed subject. Fatal primary errors remain abrupt; later cleanup errors retain their suppressed position.[1][2][7]

The replacement contract provides no additional simultaneous-publisher isolation or automatic legacy-data migration. Public outcomes and failure carriers expose replacement knowledge; they are not substitutes for observing deployed effects. Source scopes establish operation ordering, while actual database effects require the relevant integration observation.[2][4][7]

## Stored projection and verification scope

Publication retains run/version identity, captured input and environment, declarations, diagnostics, source origins, method analyses, and CFG entities. The completed-run projection excludes the full source aggregate and its annotation/type-use trees; the separate AST projection retains them under its own explicit contract. Stored names and identity algorithms are compatibility contracts, not implementation conveniences.[3][4]

Neo4j Community is the supported verification baseline. Selective role-based denial of constraint inspection is outside that baseline and remains unexecuted; this scope does not waive `SHOW CONSTRAINTS`, definition validation, tests, or quality rules. Deployment and credentials are defined in the [runbook](../../deployment/neo4j/README.md#supported-verification-scope).

## Target AST retention

Existing completed-run storage and independent completed-AST storage have separate adapters within the same Neo4j context. The [analysis contract](../contracts/analysis.md#target-publication-and-retention) owns publication eligibility. The source model owns AST qualification. Required Community integration observations are defined below. The [repository class view](../../diagrams/class/analysis-repository.puml) references those canonical domain definitions.[1][5][8]

`Neo4jRepositories.astRetention` and `Neo4jRepositories.astQuery` expose the application-owned `AstRetentionRepositoryFactory` and `AstQueryRepositoryFactory`. On `open(context)`, each factory rejects the wrong operation kind before resolving connection settings and returns the corresponding typed port on successful acquisition. The completed-run factory also checks its operation kind before settings resolution. Both AST paths use `Neo4jAstResultRepository` internally. `AstRetentionRepository.saveComplete` accepts only the acquired exact, intrinsically admitted `COMPLETE` AST. A direct retention caller is responsible for the production authenticity of the source outcome it supplies. `AstQueryRepository.find` takes the acquired exact identity. The first attempt consumes the acquired capability even if its subject fails validation. Validation precedes database work for the operation. Callers own closure of either transferred capability. The [application port crossing](../contracts/analysis.md#target-repository-failure-crossing) defines the outward failure contract.[2][5][7][8]

`Neo4jAstResultCodec` maps and decodes the full AST result for its source-model version, including source/input/environment provenance, canonical declarations, written and implicit distinctions, source nodes and ordered child roles, typed semantic targets, recursive types, annotations and defaults, body ownership, evidence states and values, coverage expectations, support and gaps, and ordered diagnostic events. The codec delegates encoding and intrinsic readmission to `source.retention.AstCodec`, which selects the format from the result identity when encoding and the exact requested identity when decoding. The source module exports the codec to the repository module. Intrinsic admission recomputes identity and completion from the payload. The adapter codec then compares the stored nodes and relationships with the complete admitted projection. Retention requires a lossless representation of the source result and its canonical references.[5][8]

`Neo4jAstResultRepository` consumes the driver records and owns the read session. Root discovery selects nodes with both `AstEntity` and `AstResult` labels and the requested `astResultKey`. If that selection is empty, the repository probes for `AstEntity` nodes in the same scope. Multiple selected roots fail in `READ`. `Neo4jStoredAstAdmission` interprets the detached facts in `DECODE` before session closure. An empty selection with no scoped nodes yields `NOT_FOUND`. An empty selection with scoped nodes or a missing, nontext, or blank root format fails admission. A nonblank unsupported format yields `INCOMPATIBLE` before loading the materialization or checking the stored profile.[5][8]

For a supported format, the repository finishes the applicable reads before admission checks the stored profile. A contradictory text profile fails, while a matching unsupported profile yields `INCOMPATIBLE` before deferred row-content errors are raised. Missing or nontext profile metadata proceeds to deferred row-error handling and, if rows are usable, to projection and codec validation. The codec's exact comparison rejects the invalid root property if validation reaches that comparison. A read or stream failure takes precedence over those admission outcomes.[5][8]

A wrongly keyed root fails in `DECODE` when the stored facts reach [projection admission](../repository/neo4j-schema.md#target-ast-retention-schema). `FOUND` requires an admitted projection, intrinsic readmission, and exact materialization equality. A `DECODE` failure stays primary. A distinct `READ_SESSION_CLOSE` failure is suppressed before any later repository-close failure. The application validates the requested identity on the returned lookup and closes the acquired repository before returning any normal result.[1][5][7][8]

After subject and projection validation, the AST adapter uses `Neo4jIdentityConstraints` to create and inspect the AST namespace's definitions in a separate schema session. The same mechanism handles the completed-run definitions. The AST schema session must close normally before replacement of the `astResultKey` scope. Managed retries reuse the immutable projection. The [phase and commit mapping](#target-phase-and-commit-mapping) defines acknowledgement, partial schema effects, and closure.[3][5][7]

Application publication failure envelopes retain the already computed AST/CFG/request outcomes, effective primary and suppressed causes, subject identity, and available replacement knowledge. Adapter phases remain on the adapter's carrier subtype. `PublicationOutcome` is separate from analysis completion. `AstRetention.retainAst` is usable after CFG refusal/failure; it does not happen automatically. The existing CLI `--persist` requests completed-run publication through the same shared coordinator; it does not request independent AST retention.[1][7]

### Exact AST replacement

Each managed write attempt first acquires the subject with `MERGE` and a key-property write. `Neo4jAstMaterialization` streams `AstEntity` nodes with the subject's `astResultKey` to a fresh `Neo4jAstReconciliation`, which compares each row with the immutable projection. The materializer deletes obsolete nodes together with their incident relationships. It removes extra labels before relabeling or updating changed nodes and creating missing ones. This ordering allows the canonical result label to be restored without colliding with a displaced label on a child. Correct existing nodes are retained.[5]

After the node phase, the materializer scans relationships whose own `astResultKey` matches the subject or whose source or target is an `AstEntity` in that scope. This includes scope-marked relationships with foreign endpoints and incident relationships with a foreign or missing relationship scope. Reconciliation compares each row by key, complete properties, exact scalar types, type, and both endpoint addresses. Selected nodes and relationships with missing or nontext keys are removed by their physical addresses. The materializer removes misplaced or malformed links, retains the first exact match for each expected relationship, removes its duplicates, and creates missing links. The adapter preserves unrelated subjects and links outside that selection. Reconciliation writes use batches of at most 512 elements.[5]

The transaction retains node addresses, canonical relationship keys, and pending changes rather than buffering complete stored graph facts. Full properties are compared as each record arrives. Physical addresses remain inside the managed write attempt that collected them; a retry collects fresh addresses. Persisted identities use application-generated keys, and the mapper computes each value key once per projection before reusing it for relationship endpoints. This follows Neo4j's transaction boundary for `elementId` and avoids repeated index and adjacency searches when applying the differences.[5][6]

### Target phase and commit mapping

Both Neo4j adapters use `Neo4jRepositoryOperation` to maintain progress for an exact application-owned context. Runtime observations are `Neo4jRepositoryOperationException`, a public subtype of `application.port.RepositoryOperationException`, with `Neo4jRepositoryPhase` owned by the adapter. No driver/session object crosses that contract. The table describes the adapter's phases; isolated failure transport and actual database effects require different observations.[2][7]

| Phase | Observation and subject-replacement knowledge on failure |
| --- | --- |
| `ACQUISITION` | Factory owns partial driver/setup cleanup until transfer; `NOT_STARTED`. Preserve primary and cleanup causes. |
| `VALIDATION` | The first AST operation checks its kind and exact subject before mapping or reading, with `NOT_STARTED`. The lifetime guard rejects reuse of a consumed AST capability before further mapping or reading and retains the prior replacement knowledge. Argument and admission failures preserve their actual family. |
| `MAPPING` | Build and validate the immutable save projection before schema work, with `NOT_STARTED`. Mapping failures preserve their actual family. |
| `SCHEMA` / `SCHEMA_SESSION_CLOSE` | Create/inspect exact constraints and close the schema session before replacement; `NOT_STARTED`. Constraint effects may remain. |
| `REPLACEMENT` | Session acquisition precedes the attempted write. Immediately before invoking managed replacement, record `UNKNOWN`; normal managed-write return establishes `KNOWN_COMMIT`. The current adapter does not infer `KNOWN_NONCOMMIT` from an exception. That generic contract value requires an authoritative noncommit observation. |
| `PUBLICATION_SESSION_CLOSE` | Carry the replacement observation; normal acknowledged save followed by close failure remains `KNOWN_COMMIT`. |
| `READ` / `DECODE` / `READ_SESSION_CLOSE` | Query exact subject; decode only supported present facts; close the read session before returning any lookup; always `NOT_STARTED`. Decode/admission/identity failures preserve their actual family. |
| `REPOSITORY_CLOSE` | Attempt enclosing close after work, carrying the operation's prior knowledge unchanged. A failed close does not prove resource release. |

Acquisition settings, driver creation, and session configuration pass through the shared acquisition translation described above. Request validation, mapping, detached admission, and intrinsic codec decoding run outside driver translation. `READ` includes the managed callback's root-cardinality check and row extraction. The callback defers recognized row-content failures for `DECODE` while it consumes the applicable streams. An escaping `Neo4jException` in a driver-work region becomes the application-port `RepositoryException`. Unmatched runtime failures retain their family. The operation carrier wraps either family afterward. If work fails, the adapter attempts accessible session cleanup. The adapter and application preserve distinct observed cleanup failures in order under the [shared failure crossing](../contracts/analysis.md#target-repository-failure-crossing), which also governs repeated throws of the primary object. Fatal errors retain the fatal primary and applicable cleanup evidence.[5][7][8]

Retry reuses the immutable projection. A callback return alone supplies no acknowledgement. An attempted managed write without a normal return leaves `UNKNOWN`. A normal managed-write return establishes `KNOWN_COMMIT` before session closure, so a later session or driver close failure carries that observation. A normal save requires acknowledgement and all internal closes. Direct AST-port users retain the single-operation lifetime contract. For a completed-run repository, driver close carries the latest established save context and its observation. If no save established a context, close carries the acquisition context.[2][7]

The application preserves the adapter carrier and classifies publication by the effective primary and replacement knowledge. The CLI's `Neo4jFailureDetailProjector` reads the Neo4j phase from that carrier, and `FailureGraphCapture` includes the projected detail in the command report.[1][7][9]

`application.internal.repository.RepositoryOperationBoundary` observes a supplier synchronously through `FutureTask.run` on the calling thread, then reads the terminal `Future.State`, `resultNow`, or `exceptionNow`. It creates no executor or background thread. `observe` preserves a carrier for the exact context and rejects a foreign-context carrier; raw runtime failures receive the observing owner's carrier. `withResource` closes after either normal work or failure; `transfer` cleans up only when construction fails before ownership transfer. Cleanup is suppressed without replacing the primary, and an original fatal primary remains abrupt. This mechanism is implementation support with a qualified module export to the repository module, not public adapter SPI or commit evidence. External adapters use the public port contracts and may implement their own observation mechanism. See the [boundary implementation](../../src/main/java/org.aquilagraph.application/org/aquilagraph/application/internal/repository/RepositoryOperationBoundary.java), `observe`, `withResource`, and `transfer`, and the [application module](../../src/main/java/org.aquilagraph.application/module-info.java).[7]

### Retention compatibility obligations

Use the distinct [AST schema namespace](../repository/neo4j-schema.md#target-ast-retention-schema); legacy `AnalysisEntity` run deletion must never delete AST-retention entities or query references. Version target AST and CFG formats and codecs; reject unsupported formats as incompatible. Graph-to-source references are qualified by `AstIdentity` and body/occurrence, with no dangling or cross-result association. Retaining a graph is optional and does not qualify AST retention. AST lookup loads no CFG; querying a legacy run cannot imply an AST exists.

Required observations include actual Community database save/close and subsequent query of a complete AST with no graph; round-trip equality of all serialized distinctions and ordering; refused/failed CFG followed by explicit AST save; unknown version and foreign graph rejection; phase-specific mapping/schema/transaction/close failures; same legacy-run replacement preserving separately retained AST. Supplied fixtures alone cannot establish compiler fidelity or persistence.

The [Community integration cases](../../src/test/java/org/aquilagraph/repository/internal/neo4j/Neo4jAstResultRepositoryNeo4jIT.java) and [isolated driver tests](../../src/test/java/org/aquilagraph/repository/internal/neo4j/Neo4jAstResultRepositoryTest.java) are verification entry points, not evidence that a current run passed. Preserve the distinction between actual server save/query/schema effects and supplied failure transport. Complete independent implementation acceptance remains [pending](java-analysis.md#model-acceptance-and-verification); historical test totals and unavailable execution logs are not carried forward as current results.
